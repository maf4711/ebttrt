# ebttrt — even better than the real thing

For multi-step engineering work:

`plan → test → implement → review → verify → remember → improve`

1. `ebttrt consult "goal"` then `ebttrt begin "goal"` — one phase skill at a time (`ebttrt next`).
2. Never skip **prove**. Review may be skipped for a one-file fix.
3. Before any "done / fixed / passing" claim: `ebttrt prove --record` then `ebttrt done`.
4. AUTOHEAL local failures. Ask before irreversible, shared, or live-money actions.
5. Prefer existing Superpowers / Ruflo / project skills. Do not invent a catalog.
6. Prior state: `ebttrt` (no args) or `~/.grok/ebttrt/current-context.md`. Not for one-line questions.
7. A Stop-nudge means verify, not "keep talking".
